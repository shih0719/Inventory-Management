## Design Specificity Verdict
LLM：產品細節有（有帳/無帳成對、AP 標籤、調整前→後預覽），但外殼是一個 1200×880「平板展示稿」移植到正式環境，全檔只有一個實質 media query（styles.css:940，只拿掉 padding/圓角）。本質上是桌面專用。
Detector：CLI 只抓到 2 個 side-tab（LoginPage.tsx:233、CreateProductModal.tsx:185），沒有任何版面規則。瀏覽器 overlay 在 6 個畫面抓到 low-contrast（#8e8a82 約 3.1–3.4:1）、9–10px undersized text、nested-cards。text-occlusion 與 nested-cards 判為誤報/風格選擇。

## Root cause
`.app-shell { overflow: hidden }`（styles.css:762）加上 `.dash`/`.batch-flow` 等容器也 overflow:hidden → 超寬內容被靜默裁掉而不是可捲動；`document.scrollWidth` 永遠是 375，掩蓋了問題。shell 實際寬 984px（375 與 768 都是）。

## Priority Issues
- [P0] 導覽列在手機與平板碰不到：`.tb` 單列不換行（styles.css:58）寬 984–1139px；進貨之後全部被裁。管理下拉選單開在 x=807。點按鈕會讓 shell 被捲到 scrollLeft=566 且回不來。Fix：≤900px 拆兩列＋漢堡選單＋底部動作列（進貨/出貨），移除 shell 的 overflow:hidden。→ adapt, layout
- [P0] 批次入庫/出庫在手機無法使用：`.batch-line` 固定欄寬最少約 718px（styles.css:463,504），數量/帳別/備註/✕ 被裁 82–401px。Fix：≤640px 每列改成堆疊卡片，送出鈕 sticky 全寬。→ adapt
- [P0] Modal 錨定文件而非視窗：`.modal-scrim { position:absolute }`（styles.css:251），捲動後 modal 在畫面外；各 modal 內嵌固定寬 600–800px；關閉鈕 13×16。Fix：position:fixed、width:min(540px,100vw-24px)、手機改 bottom sheet、44px 關閉鈕。→ harden, adapt
- [P1] 多欄 grid 沒有斷點：dashboard `.kpis` 4 欄、`.cols` 2 欄（styles.css:134,142）、出貨頁 280px+1fr 讓詳情窗只剩 35px、AP 卡片 3 欄各 100px。→ layout
- [P1] 觸控與輸入：body 13px、輸入框 12–13px 讓 iOS 每次聚焦都放大；+5/+10 晶片 16px 高、大多數控制項 <44px；掃碼欄無 autoCapitalize/inputMode/enterKeyHint；tour FAB 蓋住送出鈕。→ typeset, harden

## Persona Red Flags
- Casey（手機）：捲動後點交易沒反應（modal 在畫面外）；捲動誤觸開 modal；每次重開語言變英文；無法登出。
- Alex（熟手）：手機沒有掃碼優先路徑；交易頁 7 欄篩選牆；報表拖曳把手和觸控捲動衝突。
- Sam（無障礙）：9–11px 標籤、#8e8a82 對比不足、13×16 關閉鈕、🌐/▤ 無標籤、`<html lang="en">`、沒有可見的 focus ring（styles.css:288）。
- 倉管＋手機＋掃碼槍：批次無法輸入數量、無法切倉庫、聚焦就放大、序號不會自動大寫、送出鈕被 FAB 蓋住。快速出貨（QuickSell）是目前最接近可用的頁面，可作範本。

## Minor Observations

- 語言預設 en 且不保存（useAppState.ts:88）；登入頁固定英文、placeholder 是開發帳號（LoginPage.tsx:96,111）。

## Questions to Consider

- 報表與 dashboard 數字不一致，是說明不足還是兩邊算的東西不同？
